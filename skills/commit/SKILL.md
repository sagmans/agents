# Commit

## Related skills

Load `git` first for repository inspection. After committing, load `ship` for delivery (owned repositories push `main`; external repositories open a PR) or `pr` for PR-only work. Do not reload a skill that already called this one.

Inspect with native Git or the `git` skill's optional `summary`/`detail` reports. Create commits only through this bundled script (resolve its path relative to this skill):

```bash
bash scripts/commit.sh "type(scope): message" --body "why this change exists" -- <path>...
```

Pass a single-line Conventional Commit subject and a nonempty purpose-focused body separately. Use actual newlines for multiple body paragraphs, never literal `\n`. The required `--` separates message arguments from paths.

It refuses missing or blank bodies, multiline subjects, literal newline escapes, carriage returns, detached HEAD, the default branch of an external repository (owned repositories commit on `main`), pre-staged changes, empty selections, and invalid Conventional Commit messages. Each call stages only named paths, restores the clean index if commit fails, and executes the ultimate template exactly:

```bash
git commit -s -S -m "<subject>" -m "<body>"
```

`-S` GPG-signs; `-s` adds the DCO sign-off. Never alter Git configuration, bypass hooks, add trailers manually, add agent, provider, model, or harness attribution (`Co-authored-by:`, `Generated by`, `Generated with`), or include unrelated paths. Run relevant checks first and invoke once per atomic group. Report the resulting hash and remaining status.
